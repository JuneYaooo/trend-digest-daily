# 日报格式规范（reports/YYYY-MM-DD.md）

agent 依本规范把 `fetch_trends.py` 的规范化 JSON 渲染成每日选题建议。所有热度、排名、
链接必须取自当日 JSON，禁止编造 JSON 中不存在的条目或数字；聚合顺序是 AI 建议而非官方排名。

## 结构模板

```markdown
# 选题雷达 · {YYYY-MM-DD}（周X）

> 数据源：{成功源列表}｜共 {total_items} 条 → 去重后 {unique_items} 条
>（跨源重复 {duplicate_items}，NEW {new_items}）
> 源状态：{每源一行，不可用源写明「源不可用：原因」}

## 今日必看（按领域匹配度排序，3-5 张选题卡）

### 1. {话题名，一句人话} ｜匹配度★★★★☆｜{领域 label}
- **热度证据**：{源#排名（标签）}，如：知乎#1（热）· 微博#8（新）· HN front_page
- **发生了什么**：一句话，基于条目标题，不脑补细节
- **为什么和你有关**：一句话，说明命中的领域关键词与关联逻辑
- **可写角度**：①… ②… ③…（结合博主领域，具体到可动笔）
- **时效窗口**：如 24h 内（标签：爆）｜3 天内｜长尾
- **链接**：{原帖标题}(URL)｜{…}(URL)

## 次级观察（值得蹲但还不够热/领域相关度低）
- {条目}｜{源#排名}｜一句为什么先蹲着

## 全源速览
| # | 标题 | 来源·排名 | 热度 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | … | 微博#1 | 398487 | NEW/连续N天 |

## 趋势追踪（连续 ≥2 天在榜）
- {标题}：连续 {streak} 天在榜，首见 {first_seen}，今日 {源}#{rank}
- （首次运行无历史缓存时写：首日基线，明日开始出现连续在榜追踪）

---
*聚合顺序与切入角度为 AI 建议仅供参考；排名与热度来自各源公开榜单，口径互不可比；
发布前请点开原帖核实内容。生成：trend-digest-daily v0.1.1*
```

## 聚类与打分规则

1. **跨源聚类**：`dup_of` 非空的条目并入主条目话题；标题不同但同一事件（如「男篮不敌日本」
   与「郭士强下课」）由 agent 保守合并为一个话题，并列出全部佐证条目；拿不准就拆开。
2. **匹配度打分**：对照 `config.yaml` 的领域关键词，命中 1 个关键词 ★★，2-3 个 ★★★，
   4 个以上或直接命中账号定位 ★★★★-★★★★★；无命中的话题不进「今日必看」，
   相关度最低的进「次级观察」。`config.yaml` 缺失时输出通用版：按热度来源数量与排名给 Top 3-5。
3. **时效窗口**：带「爆/热」标签或单一来源新上榜 → 24h 内；连续在榜 → 可做深度解读；英文源 →
   注明适合编译/解读类账号。
4. **诚实红线**：某源不可用必须在「源状态」注明；NEW/streak 只能来自 JSON 的 `is_new`/`streak`
   字段；热度数字原样引用，不做跨源换算。
